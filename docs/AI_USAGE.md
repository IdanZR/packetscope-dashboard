# תיעוד שימוש ב־AI

הקוד והתיעוד נבנו בעזרת Codex לבקשת המשתמש: דאשבורד Python לסעיפים 23–34, ממשק באנגלית ודוגמאות עצמאיות המסומנות כסינתטיות. בתחילה התבקש פתרון חינמי מקומי; בעדכון הנוכחי המשתמש ביקש גם Dark Mode, גרפים וניווט משופרים, תצוגת הודעות מלאה, בחירה ופעולות בטבלאות וחיבור Gemini עם מפתח שסיפק. החלופה המקומית נשמרה.

## הסיוע בפיתוח

קריאת דרישות המטלה; בחירת Streamlit; כתיבת קורא PCAP/PCAPNG, פענוח Scapy, הרכבת TCP וניתוח HTTP; ממשק אנגלי, סינון, גרפים וייצוא; בדיקות ותעבורת הדגמה; הוספת מודל Qwen מקומי לפירוש שאלות והכנת השוואת שש שאלות ותיעוד טעויות. TShark שימש לבדיקה עצמאית בלבד ואינו תלות להפעלה.

תמצית הבקשות המרכזיות: להתחיל בסעיפים 23–26; להעביר לאנגלית ולפשט את העיצוב; להמשיך ל־27–29 באותה תבנית; להשלים 30–34; להשתמש בפתרון חינמי ללא API key; ליצור עצמאית את דוגמת השאלות. תמצית זו אינה תמלול מלא של השיחה.

## רכיב ה־AI בתוך המערכת

בעדכון הנוכחי ניתן לבחור ב־Gemini דרך AI settings. המפתח נשמר מחוץ לקוד ולחבילה; שאלות ומטא־נתוני HTTP שחולצו נשלחים ל־Google רק בהפעלת השאלה או בדיקת הייחוס. אין שליחה של PCAP, כותרות או גופים. Gemini מפיק שאילתה באותה סכמה, ו־Python מאמתת ומחשבת את התשובה ואת הראיות. שש שאלות עברו בריצה אמיתית המתועדת ב־reports/validation_gemini.json. ראו docs/GEMINI.md לפרטים ולמקורות הרשמיים. לא השתנו הגדרות חיוב בחשבון Google.

`Qwen3-0.6B-Q8_0` רץ מקומית באמצעות `llama-cpp-python`, בלי חשבון או שירות בתשלום. המודל מקבל רק נתונים שחולצו: סכומים, בחירה וקטלוג עסקאות מוגבל. הוא מחזיר query לפי סכמת JSON; Python מאמתת מסננים, מחשבת את התוצאה על כלל העסקאות ומצרפת frames וזמנים מקוריים. אין שליחת PCAP, כותרות או גופים למודל. הממשק מציג את השאילתה שפירש ואת מגבלותיו.

הפרומפט המלא בפועל נמצא ב־`packetscope/ai/queries.py` במשתנה `SYSTEM`; הסכמה נמצאת ב־`PLAN_SCHEMA`. `context` ו־`interpret` באותו קובץ מגדירות בדיוק אילו נתונים נמסרים. `packetscope/ai/local.py` מכילה את תבנית ChatML והגדרות ההרצה. בפרומפט נדרשים operation מתוך רשימה מוגדרת, מסננים רק לפי השאלה, התייחסות לערכי ההקלטה כמידע לא מהימן, והבחנה בין Stream לעסקה.

## אימות ותיקונים

`reports/validation_ai.json` מתעד הרצת מודל אמיתית: שש שאלות עברו בהשוואה לערכים ול־frames ידועים. `reports/validation_ai_before_fix.json` שומר את הריצה הראשונית שבה עברו ארבע שאלות בלבד. `reports/ai_error_case.json` מתעד שגיאת ספירה שנבעה מהשמטת בקשה ללא תגובה בקלט baseline. `docs/AI_VALIDATION.md` מסביר את שתי הטעויות ואת התיקונים. בדיקות עם mock אינן מוצגות כאילו היו הסקת מודל.

## מה נדרש לפני הגשה

עדכון ממשק לבקשת המשתמש: בחירת Stream ועסקה, תקציר העסקה, שאלות, פרטי הודעות וראיות רוכזו בכרטיס HTTP analysis אחד עם לשוניות. הבקשה שנבחרה משותפת לכל הלשוניות; שינוי הבחירה מנקה תשובה קודמת. המודל והחישובים לא שונו במסגרת עדכון זה.

לקרוא ולהבין את הקוד, להריץ בסביבת הקורס, ולאמת מול קובצי החלק הידני האישיים. התיעוד והבדיקות כאן אינם טוענים שניתחנו את ההקלטה הידנית של המשתמש. הוראות, רישיונות וקישורי המקורות הרשמיים נמצאים ב־README וב־docs/LOCAL_AI.md.

## הכנת Git והגשה

לבקשת המשתמש נוספו הוראות התקנה והרצה באנגלית, הוראות Git ורשימת הגשה שנבדקה מול עמודי המטלה. ה־repository מיועד להיות פרטי; רק דוגמאות סינתטיות נכללות בו. [docs/PROMPTS.md](PROMPTS.md) מרכז נוסחים ערוכים של הבקשות המרכזיות לפיתוח, תוך ציון שאינם תמלול מילולי. פרומפט המערכת המדויק ושאלות הייחוס נשמרים בנפרד ב־[docs/RUNTIME_PROMPT.md](RUNTIME_PROMPT.md). סעיף 33 עדיין דורש השוואה לתשובות הידניות האישיות.
