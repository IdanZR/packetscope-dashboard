# PacketScope — הערות ניתוח מפורטות

כלי Python לחלק ג׳, סעיפים **23–34**, עם ממשק אנגלי, מצבי Light/Dark וניווט בלשוניות. Scapy מפענחת חבילות; אפשר לפרש שאלות בעזרת **Gemini** עם מפתח API, או **Local Qwen** החינמי שעובד ללא מפתח וללא אינטרנט לאחר ההתקנה. ניתוח הקובץ מקומי; Gemini מקבל רק שאלה ומטא־נתוני HTTP שחולצו. הדגמת סעיף 33 מבוססת על תשובות ידועות בהקלטה סינתטית, ואינה מוצגת כחלק הידני האישי שלכם.

## הפעלה

דרוש Python 3.12 או 3.13, דפדפן וחיבור לאינטרנט להתקנה הראשונה בלבד. אין צורך ב־Npcap, הרשאות מנהל או כרטיס רשת פעיל לצורך ניתוח קבצים.

שימוש ב־Gemini דורש גם חיבור לאינטרנט בזמן השאלות. הזינו מפתח בשדה המוסתר ב־**AI settings**, או הגדירו `GEMINI_API_KEY` בסביבת ההרצה. אין להכניס מפתח לקוד או ל־ZIP. הגדרות, פרטיות, שמירת המפתח ובדיקות מתוארות ב־[GEMINI.md](GEMINI.md). המכסות והתמחור נקבעים בחשבון Google; החלופה המקומית נשארה זמינה.

פתחו מסוף בשורש הפרויקט, בתיקייה שבה נמצא app.py, והריצו:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

אם מותקן Python 3.13, החליפו את `-3.12` ב־`-3.13`. אם הפקודה `py` אינה קיימת, השתמשו ב־`python`. ב־macOS/Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

אפשר גם להריץ ב־Windows את `start.bat`, שמכין סביבה מקומית בהפעלה הראשונה. כתובת הממשק: http://127.0.0.1:8501. עצירה: Ctrl+C בחלון המסוף. אין צורך לשנות Execution Policy.

**להפעלת השאלות החינמיות:** הריצו פעם אחת `scripts/setup_ai.bat`, שמתקין את ספריית ה־CPU ומוריד מודל בגודל כ־640 MB; אחר כך הפעילו את `start.bat`. לאחר ההתקנה השאלות פועלות ללא אינטרנט. הוראות ידניות, מקורות ורישיונות נמצאים ב־[LOCAL_AI.md](LOCAL_AI.md). ההתקנה כבר בוצעה במחשב הפיתוח; קובצי המודל אינם כלולים ב־ZIP.

## שימוש והצגה

הניווט הראשי כולל **Traffic overview**, **HTTP & AI**, **Packets & endpoints**, **Reports**. אפשר לבחור **Light**, **Dark** או **System** בתפריט **⋮** בפינה העליונה. צבעי הגרפים, הטבלאות והקוד מותאמים למצב הנבחר.

הגרפים כוללים נפח לאורך זמן, התפלגות פרוטוקולים, כתובות פעילות לפי נפח, 15 בקשות HTTP האיטיות ביותר והתפלגות תוצאות HTTP. מעבר עם העכבר מציג ערכים וראיות; הגרפים ניתנים להגדלה ולהורדה. גרפי HTTP מתייחסים תמיד להקלטה המלאה, ומסומנים בהתאם.

בחרו שורה בטבלת עסקאות HTTP כדי לעדכן את העסקה המשותפת לשאלות ולפרטים. בטבלת כתובות אפשר לבחור כתובת, לסנן אליה את התעבורה או לייצא את חבילותיה. בטבלת חבילות אפשר לבחור frame, להוריד את המטא־נתונים שלו ולעבור לעסקת HTTP קשורה. כל מספור frame נשאר לפי הקובץ המקורי.

1. המערכת נפתחת בהקלטת **הדגמה סינתטית** המסומנת במפורש. היא אינה תשובה לחלק הידני שלכם.
2. באזור Open a capture בראש העמוד בחרו קובץ `.pcap` או `.pcapng`. אפשר גם `.cap` אם התוכן הוא PCAP. **PNG הוא תמונה ואינו נתמך.**
3. צלמו את אזור Capture overview: מספר החבילות, תחילת ההקלטה, סיומה ומשכה.
4. בדקו את גרף הנפח לאורך זמן, גרף Packets by protocol וטבלת כתובות הקצה.
5. סננו לפי פרוטוקול וכתובת. לשונית Packets מציגה מספרי frame מקוריים ופרטי חבילות לצורך אימות.
6. אפשר להוריד סיכום JSON וטבלת CSV. הסיכום כולל hash של הקובץ, מדדים מלאים ומסוננים, הגדרות סינון ואזהרות.

## הגדרות החישוב

- כל המדדים העליונים מתייחסים להקלטה המלאה. הגרפים, הטבלאות והייצוא מתעדכנים לפי הסינון.
- הזמנים מוצגים ב־UTC, ללא תלות באזור הזמן של המחשב. ההתחלה והסיום הם זמני החבילות שנשמרו, ולא זמני לחיצה על כפתורי Capture.
- האורך המקורי (`wire_bytes`) והאורך שנשמר (`captured_bytes`) נשמרים בנפרד. נפח הגרפים מבוסס על האורך המקורי המדווח בקובץ, כולל כותרות. הוא אינו מדידת goodput או כלל תקורת הקו הפיזי.
- כל חבילה מקבלת **סיווג ראשי אחד**. למשל חבילת HTTP נספרת כ־HTTP, ועמודת `layers` מציגה גם IP ו־TCP. לכן הספירה שונה מטבלת Protocol Hierarchy שבה אותה חבילה נספרת בכמה שכבות.
- HTTP/1.x מזוהה לפי שורת בקשה/תגובה בתחילת מטען TCP. TLS מזוהה לפי מבנה אפשרי של כותרת רשומה. זה זיהוי ראשוני; בטבלת הפרוטוקולים הסיווג הוא לפי חבילה; אזור HTTP transactions מבצע בנפרד הרכבת TCP והתאמת הודעות HTTP/1.x. אין פענוח הצפנה, HTTP/2 או זיהוי QUIC. חבילות ACK והמשך עשויות להיספר כ־TCP. מספר פורט לבדו אינו נחשב הוכחה לפרוטוקול יישום.
- כתובות IP כוללות IPv4/IPv6 וכתובות ARP. אם אין IP, מוצגות כתובות MAC. אין זיהוי של בעל הכתובת ואין פנייה לשירות DNS חיצוני.
- נפח כתובת קצה כולל תעבורה שבה היא מקור או יעד. סיכום כל הכתובות עשוי לספור אותה חבילה פעמיים. חבילת loopback נספרת פעם אחת במעורבות הכתובת, ופעם בכל כיוון.
- הגרף כולל עד 60 חלונות שווים בין הזמן הראשון לאחרון בסינון. הציר מציג שניות מתחילת התעבורה המסוננת; חלונות ריקים מוצגים כאפס. אין המרה לקצב ביטים.

## תמיכה ומקרי קצה

PCAP רגיל ו־nanosecond, שני סדרי בתים; PCAPNG עם כמה ממשקים ו־sections, רזולוציית זמן עשרונית/בינארית ו־timestamp offset. נתמכים Enhanced Packet Block, Simple Packet Block ו־Packet Block הישן. בלוקים אחרים של מטא־נתונים מדולגים לפי אורכם.

קובץ תקין ללא חבילות מציג מצב ריק. חבילה בודדת מקבלת משך 0. חבילות PCAPNG ללא זמן נשארות בספירה ואינן נכנסות לגרף הזמן; אין המצאת זמן. חותמות זמן מחוץ לסדר מטופלות לפי מינימום/מקסימום. קישור שאינו נתמך או חבילה שלא פוענחה מסומנים Unknown וממשיכים להיכלל בספירה. כשל במבנה הקובץ גורר דחיית הקובץ כולו.

מגבלות V1: קובץ לא דחוס עד **100 MiB** ועד **250,000 חבילות**; קובץ גדול מדי נדחה עם הודעה, ללא הצגת תוצאה חלקית. הקובץ והמטא־נתונים נמצאים בזיכרון סשן הממשק. לא נבדקו עדיין ביצועים על הקלטה אמיתית בגבול הגודל או תאימות לסביבת הקורס שטרם נמסרה.

## עסקאות HTTP — סעיפים 27–29

אזור **HTTP analysis** בלשונית **HTTP & AI** מרכז את סעיפים 27–34 במקום אחד. בחרו **Stream for questions** ואז **Select a transaction** באותו כרטיס, או בחרו שורה בטבלת העסקאות. התקציר מציג סטטוס, זמן ו־frames; הלשוניות **Ask AI**, **Request & response**, **Packet evidence** משתמשות באותה בחירה. מעבר לבחירה אחרת או לספק AI אחר מנקה תשובה קודמת, ומשאיר את נוסח השאלה לשימוש חוזר.

**Browse and filter transactions** פותח את טבלת העסקאות והסינון לפי Host ומצב. הסינון מצמצם את אפשרויות הבחירה; שאלות כלליות כמו הבקשה האיטית ביותר וספירת Host עדיין מחושבות מכל עסקאות ההקלטה. סינון גרפי התעבורה אינו משנה אזור זה.

הטבלה מציגה את Method, Host, URI, Status, זמן התגובה, מספרי ה־frame ומצב ההתאמה. שדות כתובות הלקוח והשרת והפורטים מוצגים בלשונית **Request & response**, לצד הכותרות ותצוגה מקדימה של הגוף. לשונית **Packet evidence** כוללת את ה־frames המקוריים והורדת העסקה כ־JSON. סיכום ההקלטה המיוצא כולל גם את כל עסקאות ה־HTTP.

### הגדרות זמן ו־frame

מספרי ה־frame הראשיים מציינים את החבילה שבה הודעת HTTP הושלמה מתוך הבתים שנקלטו. זו יכולה להיות חבילת ההמשך האחרונה. אם הגוף אינו שלם, מצוין frame השלמת הכותרות, והגוף מסומן כחלקי. בפרטי ההודעה מופיעים בנפרד frame הבייט הראשון, frame השלמת הכותרות, frame ההשלמה ורשימת חבילות הראיה.

זמן התגובה הראשי הוא זמן השלמת התגובה הסופית פחות זמן השלמת הבקשה. אם הודעה אינה שלמה, חסרים זמנים או הסדר הזמני הפוך, מוצג N/A. בנוסף מופיע **First-byte delay**, מהבייט הראשון בבקשה לבייט הראשון בתגובה הסופית. אין לפרש זאת כזמן עיבוד שרת בלבד. בהצלבה על קובצי הדוגמה זמני ההשלמה ומספרי ה־frame תואמים ל־TShark; בהקלטה חלקית או פגומה יכולים להיות הבדלים בין מנתחים.

### תמיכה ומגבלות HTTP

הרכבה לפי מספרי TCP sequence, ללא שכפול הודעות בגלל retransmission; תמיכה בחבילות מחוץ לסדר, sequence wrap, חיבורים מתמשכים ו־pipelining. תגובות מותאמות לפי סדר ההודעות באותו חיבור, עם בדיקת כיוון ו־ACK. חיבור חדש עם SYN מקבל מזהה נפרד. המזהה הוא פנימי לדאשבורד ואינו מספר ה־stream של Wireshark.

גבולות גוף ההודעה נקבעים לפי Content-Length, העברת chunked, כללי HEAD ו־1xx/204/304 או סיום חיבור כשנדרש. תגובות ביניים 1xx מוצגות בנפרד ואינן נחשבות לתגובה סופית. אחרי CONNECT מוצלח או 101 אין ניסיון לפרש את המנהרה כ־HTTP נוסף.

חורים ב־TCP, חפיפות עם תוכן סותר או framing עמום מבטלים התאמה אוטומטית באותו חיבור ומוצגת אזהרה. מופיעים גם No response captured, No request captured ו־Uncertain; ערכים חסרים אינם מנוחשים. היעדר בקשה או תגובה עשוי לנבוע מתחילת הקלטה מאוחרת או מסיומה המוקדם, ולא מעיד בהכרח על תקלה ברשת.

אין תמיכה בפענוח HTTPS, HTTP/2, HTTP/3 או בהרכבת פיצולי IP. תחילת stream שאינה גבול הודעת HTTP מזוהה אינה נסרקת בחיפוש אחר טקסט שנראה כמו בקשה. **Raw message** מציג את הודעת ה־HTTP שנקלטה, כולל כותרות וגוף wire, עם מספרי שורות והורדה ללא שינוי של הבתים המקוריים כ־`.http`. כברירת מחדל התצוגה מוגבלת ל־256 KiB; בהודעה גדולה אפשר להפעיל תצוגה מלאה או להוריד את כל הבתים. הודעה חלקית מסומנת. גוף בינארי או דחוס אינו בהכרח קריא כטקסט. **Body preview** נשאר תצוגה עד 2 KiB אחרי הסרת מסגור chunked; gzip אינו מפוענח. גבולות ההרכבה נשארו 4 MiB לכיוון, 32 MiB בסך הכול ו־10,000 עסקאות; חריגה מסומנת, והמדדים הכלליים נשארים מלאים.

### דוגמת HTTP מורחבת

להדגמת כמה עסקאות, הפעילו Use sample capture ובחרו HTTP transactions ברשימת Sample capture. אפשר גם להעלות את `sample_data/http_transactions.pcap` או את גרסת PCAPNG שלה. ההקלטה סינתטית ומכילה באותו חיבור:

| בקשה | תגובה | Frames | זמן תגובה |
|---|---|---|---|
| GET /home | 200 | 1 → 3 | 500 ms |
| GET /missing | 404 | 4 → 5 | 250 ms |
| POST /form | 201, chunked | 6 → 7 | 250 ms |
| GET /pending | לא נקלטה תגובה | 8 → N/A | N/A |

התגובה הראשונה מפוצלת בין frames 2–3. קובץ `reports/validation_http.json` מתעד את הצלבת התוצאות מול TShark בשני הפורמטים. הבדיקות האוטומטיות מכסות את מנוע ההקלטה, ניתוח HTTP, מנוע התשובות והממשק. ראו docs/VALIDATION.md לתוצאות. בדיקות אלה אינן תחליף להשוואה מול ההקלטה האמיתית שלכם.

מקורות כללי הפרוטוקול: [HTTP/1.1, RFC 9112](https://www.rfc-editor.org/rfc/rfc9112.html) ו־[TCP, RFC 9293](https://www.rfc-editor.org/rfc/rfc9293.html).
